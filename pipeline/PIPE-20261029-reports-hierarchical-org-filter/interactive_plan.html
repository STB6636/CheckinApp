แผนปรับปรุงหน้ารายงาน: เพิ่มฟิลเตอร์กรองข้อมูลโครงสร้างลำดับชั้น

Pipeline: PIPE-20261029-reports-hierarchical-org-filter | Branch: feature-reports-hierarchical-filter

วัตถุประสงค์และความต้องการ

ในหน้ารายงานการลงเวลา (reports.html) สำหรับผู้ใช้งานระดับ SuperAdmin และ Admin ขอบเขตสำนักงาน/กอง ให้เพิ่มแถบฟิลเตอร์ Dropdown ลำดับชั้น 3 ระดับ: [สำนักงาน/กอง] > [ส่วน/ฝ่าย] > [กลุ่มงาน] โดยมีค่าเริ่มต้นของทุกช่องเป็น "แสดงทั้งหมด" และสัมพันธ์กันเป็นทอดๆ (Cascading)

มาตรการความปลอดภัยตามข้อควรระวัง (Strict Safeguards)

  • ตารางและปุ่ม TAG ทำงานปกติ: การคลิกเลือก TAG สถานะ (#statusTagsFilterContainer) ยังคงแสดงแยกตารางตาม TAG ที่เลือกได้อย่างสมบูรณ์
  • คอลัมน์และ Layout ปกติ: ไม่มีการแก้ไขโครงสร้างคอลัมน์ตารางหรือ Colspan ใดๆ คอลัมน์พิกัด GPS, เวลาเข้า-ออก, หมายเหตุ และปุ่มจัดการยังคงแสดงผลตามระเบียบเดิม 100%
  • การคลิกแถวเปิดโปรไฟล์: การคลิกแถวเพื่อเปิดดูฟอร์มโปรไฟล์เฉพาะรายการ (#modalPersonnelResumeProfile) ทำงานผ่าน Event Delegation ได้อย่างถูกต้อง

รูปแบบจำลองแถบฟิลเตอร์ลำดับชั้น (Hierarchical Filter Dock)

3-Tier Cascading Filter
กรองข้อมูลตามโครงสร้างองค์กร (ขอบเขต สำนักงาน/กอง):
1 โครงสร้าง HTML ใน reports.html

เพิ่มบล็อก #hierarchicalOrgFilterDock ไว้ระหว่างแถบเลือกวันที่และแถบ TAG สถานะ โดยตั้งค่าเริ่มต้นเป็น hidden

2 ตรรกะสิทธิ์และการสืบทอด Dropdown

แสดงแถบฟิลเตอร์เฉพาะ SuperAdmin และ Admin Bureau พร้อมผูก Event change อัปเดตตัวเลือกลำดับถัดไปแบบอัตโนมัติ

3 การกรองข้อมูลแบบ Multi-Layer

นำค่าฟิลเตอร์องค์กรไปประมวลผลร่วมกับ TAG สถานะ ผ่านเมธอด #getFilteredRecords() ส่งผลลัพธ์ให้ตาราง, พิมพ์ PDF และ Excel โดยตรง

  • SubAgent 2 (QA Auditor - Model: Flash 3.8 High): ตรวจทานความถูกต้องของฟิลเตอร์ 3 ระดับ ทดสอบการคลิก TAG แสดงตาราง และเทียบความแตกต่างกับ Branch main
  • Orchestrator: ควบคุมกระบวนการ, อัปเดต Second Brain, รัน AST Mapper (vscode_ast_mapper.mjs) และ Commit/Push ขึ้นสู่ Branch feature-reports-hierarchical-filter
