ระบบ Realtime DOM Diffing & Concurrency Engine (รองรับ Admin หลายคนพร้อมกัน)

ครอบคลุมทั้ง 5 หน้าหลัก: หน้าภาพรวม (ทุกการ์ดทุกตาราง), หน้ารายงานการลงเวลา (ทุกตาราง), หน้าอนุมัติลงเวลากรณีพิเศษ, หน้าจัดการข้อมูลบุคลากร และ หน้าจัดการบัญชีผู้ใช้งาน พร้อมระบบป้องกัน Race Condition / Double Action Shield เมื่อมีแอดมินมากกว่า 2 คนดูแลระบบเดียวกันในหน้าจอเดียวกัน

รอการอนุมัติ (Proceed) จากผู้ใช้
1. Silent DOM Diffing (ไร้ Skeleton)

ไม่เรียก showLoading หรือล้างตารางทิ้ง แต่ตรวจจับความต่างระดับ Row ด้วย data-row-id แทรกเฉพาะแถวใหม่ ลบแถวเก่า และอัปเดตเฉพาะ Cell ที่เปลี่ยน

2. Multi-Admin Concurrency Shield

เมื่อ Admin A กดอนุมัติ/จัดการ หน้าจอ Admin B จะล็อกปุ่มแถวนั้นทันที แสดงข้อความ "อนุมัติแล้ว โดย Admin A" ป้องกันการกดย้ำซ้ำซ้อน (Zero 409 Race Condition)

3. Dynamic Sequence Re-Indexing

ฟังก์ชัน reindexTableSequence() จะคำนวณและรันหมายเลข "ลำดับ 1, 2, 3..." ใหม่ทั่วทั้งตารางอัตโนมัติ ไม่ว่าจะมีการแทรกแถวใหม่หรือลบแถวออก

4. Zero State Loss & Dirty Form Guard

คงตำแหน่ง Scrollbar, ไม่กระทบ Checkbox ที่กำลังเลือก และหากแอดมินเปิด Modal แก้ไขอยู่แล้วข้อมูลถูกแก้ จะมีแถบเตือนไม่ให้เขียนทับข้อมูลของกันและกัน

ตารางวิเคราะห์การจัดการ Concurrency ในกรณี Admin มากกว่า 2 คน (Resolution Matrix)

กรณีปัญหา (Scenario) ความเสี่ยงเดิม (Risk) แนวทางแก้ไขในแผนงานใหม่ (Delta Engine Solution) ผลลัพธ์ UX
1. อนุมัติคำขอเดียวกันพร้อมกัน เกิด 409 Race Condition / สถานะ Audit Log ขัดแย้ง ทันทีที่ Admin A กด ปุ่มในจอ Admin B จะถูก Disabled ทันที และเปลี่ยนป้ายเป็น "อนุมัติแล้ว โดย Admin A" พร้อมเงื่อนไข Idempotent UPDATE ในฐานข้อมูล ไร้ข้อผิดพลาด
2. ติ๊ก Checkbox หลายรายการเพื่อ Bulk Approve Admin A จัดการบางรายการไปแล้ว แต่ในชุดเลือกของ Admin B ยังค้างอยู่ ระบบถอด `id` นั้นออกจาก `selectedIds` ของ Admin B อัตโนมัติ ปรับตัวเลขนับ และแสดง Toast แจ้งเตือนสั้นๆ โดยไม่ล้างรายการอื่นที่ Admin B เลือกไว้ ไม่เสียงานที่เลือก
3. แก้ไขฟอร์มบุคคลเดียวกัน Admin คนที่สองบันทึกทับข้อมูลที่ Admin คนแรกเพิ่งแก้ไขไป (Dirty Overwrite) เปรียบเทียบ `updated_at` หากหน้าต่าง Modal เปิดอยู่ จะแสดงแถบเตือนสีส้ม "ข้อมูลเพิ่งถูกอัปเดตโดย Admin อื่น" พร้อมปุ่มเปรียบเทียบข้อมูล ป้องกันทับข้อมูล
4. ลำดับในตาราง (ลำดับที่ 1, 2, 3...) ตัวเลขลำดับกระโดด ฟันหลอ หรือเรียงซ้ำกันเมื่อมีแถวถูกลบ/แทรก ฟังก์ชัน `DOMDiffHelper.reindexTableSequence()` ทำการวนนับเฉพาะแถวที่ยังแสดงผลอยู่ใหม่ทุกครั้งหลังเกิดการแทรก/ลบ รันเลขต่อเนื่อง 100%
