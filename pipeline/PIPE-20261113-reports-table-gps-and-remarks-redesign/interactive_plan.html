สคีม่าเป้าหมาย: เฉพาะ `staging` เท่านั้น (ยังไม่ยุ่งกับ `public`) • ปรับคอลัมน์และ CRUD ให้ครบถ้วนตามความเป็นจริง ไร้ Fallback

เพิ่มคอลัมน์เก็บ ลักษณะงานนอกสถานที่ (offsite_reason) และ โหมดขาออกงาน (check_out_location_mode) ใน staging.attendance_logs พร้อมปรับโค้ด CRUD ใน CheckinController.js และ AttendanceModel.js ให้บันทึกตรงเข้าคอลัมน์จริงโดยไม่เกิดปัญหาเขียนทับข้อมูลขาเข้างาน และรองรับตารางรายงาน 5 TAG (GPS 2 บรรทัด ไร้พิกัดตัวเลข) อย่างสมบูรณ์

คำสั่ง SQL Migration สำหรับสคีม่า `staging` (รันใน Supabase SQL Editor)

รันเฉพาะสคีม่า staging เท่านั้น ปลอดภัย ไม่กระทบสคีม่า public

-- เพิ่มคอลัมน์ใหม่สำหรับเก็บลักษณะงานนอกสถานที่และโหมดขาออกงานใน staging.attendance_logs
ALTER TABLE staging.attendance_logs
ADD COLUMN IF NOT EXISTS offsite_reason TEXT DEFAULT NULL,
ADD COLUMN IF NOT EXISTS check_out_location_mode TEXT DEFAULT 'ONSITE',
ADD COLUMN IF NOT EXISTS check_out_distance_from_official_meters DOUBLE PRECISION DEFAULT NULL,
ADD COLUMN IF NOT EXISTS check_out_offsite_reason TEXT DEFAULT NULL;
1. วงจรการบันทึกเวลา (Check-in / Out Lifecycle)
  • ขาเข้างาน: บันทึก location_mode + offsite_reason (เช่น อบรม, ประชุม, WFH) + distance_from_official_meters
  • ขาออกงาน: บันทึก check_out_location_mode + check_out_offsite_reason โดย ไม่เขียนทับ remark หรือ offsite_reason ของขาเข้างาน
  • กะนอกเวลา (OT) & Single-Click: บันทึกทั้ง location_mode และ offsite_reason ครบถ้วน
  • คำขอพิเศษ: บันทึกเหตุผลคำขอลงใน remark แยกอิสระ
2. ตารางรายงาน 5 TAG & จุดเชื่อมโยง 3 จุด
  • GPS เข้า/ออกงาน (2 บรรทัด): บรรทัดที่ 1 = [ในสถานที่, นอกสถานที่], บรรทัดที่ 2 = [บริเวณ..., ใกล้เคียง...] ไร้ค่าพิกัดตัวเลข 100%
  • หมายเหตุ: ตัดสถานะ TAG ตารางออกทั้งหมด (เช่น มาสาย, ปฏิบัติงานปกติ)
  • ในสถานที่: แสดง - (ไม่แสดงข้อความใดๆ ตามกฎ 2.1.1 & 2.3.1)
  • นอกสถานที่: แสดงข้อมูลตามตัวเลือก rec.offsite_reason
  • จุดเชื่อมโยง 3 จุด: หน้าต่างโปรไฟล์ย่อ (#modalResumeProfile), ตารางประวัติส่วนตัวใน checkin.html, และฟอร์มแก้ไขเวลาแอดมิน ปรับให้อ่านและรักษา offsite_reason ครบถ้วน
  • ส่งออก 3 ทาง: Web DOM, Print PDF, และ Excel XLSX ตรงกัน 100%
