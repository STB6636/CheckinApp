# ==========================================
# SECOND BRAIN & SKILL EXECUTION PROTOCOL (MANDATORY)
# ==========================================

ในการทำงานทุกครั้ง คุณจะได้รับข้อมูล `injected_knowledge` (จากสมองที่สอง) และ `active_skills` (จากคลังสกิล) แนบมาใน Payload จาก Orchestrator คุณต้องปฏิบัติตามกฎต่อไปนี้โดยไม่มีข้อยกเว้น:

## 1. ลำดับความสำคัญของการปฏิบัติตามคำสั่ง (Hierarchy of Authority)
1. **ลำดับสูงสุด (Active Skills)**: หากมีสกิลถูกแนบมาใน `active_skills` คุณต้องยึดถือขั้นตอน (`Mandatory Execution Steps`), โครงสร้างโค้ด (`Reference Templates`) และกฎเหล็ก (`Strict Rules`) ในสกิลนั้นเหนือกว่าวิธีเขียนโค้ดทั่วไปของคุณ ห้ามดัดแปลงสถาปัตยกรรมของสกิลเว้นแต่เป็นการเปลี่ยนชื่อตัวแปร/ตารางให้เข้ากับโดเมนของโปรเจกต์ปัจจุบัน
2. **ลำดับรองลงมา (Second Brain Knowledge)**: คุณต้องปฏิบัติตาม Architecture Decision Records (ADR) และหลีกเลี่ยงข้อผิดพลาดที่ระบุไว้ใน `past_pitfalls_to_avoid` จากสมองที่สองอย่างเคร่งครัด

## 2. การรายงานการใช้สกิล (Skill Execution Audit Log)
ที่ส่วนต้นสุดของผลลัพธ์ที่คุณตอบกลับ Orchestrator ทุกครั้ง คุณต้องแสดงตารางหรือบล็อกยืนยันการใช้งานสกิลและสมองที่สองดังนี้:
- **Applied Second Brain Notes**: [ระบุ ID และชื่อโน้ตจากสมองที่สองที่นำมาใช้ควบคุมการทำงานในขั้นตอนนี้]
- **Executed Skills**: [ระบุ `skill_id` ที่นำมาใช้ พร้อมยืนยันว่าได้ตรวจสอบครบตาม `Self-Verification Checklist` ของสกิลนั้นทุกข้อแล้ว]

## 3. การเสนอแนะเพื่อสกัดสกิลใหม่ (Skill Candidate Flagging)
หากในระหว่างที่คุณออกแบบระบบหรือเขียนโค้ดในขั้นตอนนี้ คุณได้สร้างลอจิก โครงสร้างโค้ด หรือโซลูชันที่ซับซ้อนซึ่งยังไม่เคยมีอยู่ใน `active_skills` และเห็นว่าสามารถนำไปใช้ซ้ำในอนาคตได้ ให้คุณติดป้ายกำกับท้ายผลลัพธ์ดังนี้เพื่อแจ้งให้ `agent_08_skill_smith` ทราบในขั้นตอนที่ 6:
```markdown
### [SKILL_CANDIDATE]
- **Proposed Skill Name**: <ตั้งชื่อสกิลที่แนะนำให้สกัด>
- **Source Files/Modules**: <ระบุไฟล์หรือฟังก์ชันที่คุณเพิ่งเขียนเสร็จซึ่งเป็นต้นแบบของสกิลนี้>
- **Reusability Rationale**: <อธิบายว่าทำไมส่วนนี้จึงควรสกัดเก็บเข้าคลังสกิล>
```
