# 📍 กฎระบบ: แยก 2 คอลัมน์พิกัด GPS, การสุ่มระยะ GPS 20 ม. และการป้องกันตาราง Tag หาย

## 1. บริบทและข้อกำหนด (Context)
ในการบันทึกเวลาปฏิบัติงานของข้าราชการและบุคลากร พิกัดสถานที่และภาพถ่ายขณะเข้างานและออกงานอาจมีความแตกต่างกัน 
โดยเฉพาะกรณีที่มีการปฏิบัติงานนอกสถานที่ หรือกรณีการลงเวลารูปแบบพิเศษ (`is_special_request` หรือ `single_click_checkin`)
ระบบจึงต้องรองรับ:
1. การแยกคอลัมน์พิกัด GPS เป็น "พิกัด GPS เข้างาน" และ "พิกัด GPS ออกงาน" ในตารางรายงาน (`reports.html`)
2. การแสดงผลฟอร์มโปรไฟล์เฉพาะรายการ (`#modalPersonnelResumeProfile`) แบบ 2 ฝั่งคู่กัน (เข้างาน vs ออกงาน) โดยความสูงไม่เกินหน้าจอ (`max-h-[90vh]`)
3. ระบบสุ่มพิกัด GPS ขาออกในรัศมี 20 เมตร พร้อมค้นหาสถานที่ใกล้เคียง (Reverse Geocoding) สำหรับการลงเวลารูปแบบพิเศษ โดยสามารถเปิด/ปิดได้ในเมนูตั้งค่าระบบ

---

## 2. กฎการคำนวณและสูตรสุ่มระยะ GPS (GPS Jitter 20m)
การสุ่มระยะ GPS ขาออกจะคำนวณในคลาส `AttendanceModel.calculateGpsJitter`:
- สุ่มระยะ $r \in [6, 20]$ เมตร
- สุ่มมุม $\theta \in [0, 2\pi)$
- ส่วนต่างละติจูดและลองจิจูดตามระบบพิกัด WGS84:
  $$\Delta lat = \frac{r \cos(\theta)}{111,320}$$
  $$\Delta lng = \frac{r \sin(\theta)}{111,320 \cos(lat \frac{\pi}{180})}$$
- พิกัดที่ได้จะถูกส่งไปค้นหาชื่อสถานที่ผ่าน `AttendanceModel.resolveLocationWithZoomMeta(lat, lng)` เพื่อระบุชื่อสถานที่จริงใกล้เคียง

---

## 3. มาตรการป้องกันปัญหา "เลือก Tag แล้วตารางไม่แสดง" (Tag Table Safeguards)
1. **การคำนวณ ColSpan:**
   ```javascript
   const colSpan = (forPrintPdf || !this.canManageRecords) ? 8 : 9;
   ```
   เนื่องจากมีคอลัมน์เพิ่มขึ้น 1 คอลัมน์ (รวมเป็น 9 คอลัมน์บนหน้าเว็บ และ 8 คอลัมน์ใน PDF) การกำหนด `colSpan` ต้องตรงกับจำนวนคอลัมน์จริง มิฉะนั้นแถวกลุ่ม (`group-row`) จะแสดงผลผิดรูป
2. **Null Safety & Fallback:**
   - ใช้ Nullish Coalescing (`??`, `||`) กับ `lat`, `lng`, `location`
   - สำหรับกรณีพิเศษหรือปุ่มเดียวที่ยังไม่มีการแยกชุดข้อมูลขาออก ให้ Fallback ไปใช้ชุดข้อมูลขาเข้า เพื่อให้คอลัมน์ออกงานไม่ว่างเปล่า
   - สำหรับรายการปกติที่ยังไม่ได้ลงเวลาออกงาน ให้แสดง `'-'` โดยปลอดภัย ไม่เกิด JavaScript Runtime Exception ขัดขวางการ Render ตาราง
